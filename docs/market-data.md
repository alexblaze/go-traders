# Market data

## Provider abstraction

```ts
interface MarketDataProvider {
  getSymbols(): Promise<Stock[]>;
  getQuote(symbol: string): Promise<Quote>;
  getHistoricalPrices(symbol: string, from: Date, to: Date, timeframe: Timeframe): Promise<OHLCV[]>;
  getMarketSummary(): Promise<MarketSummary>;
}
```

| Provider | `MARKET_DATA_PROVIDER` | Source label | Notes |
|---|---|---|---|
| `CsvProvider` | `csv` (default) | `IMPORTED` (or `DEMO` if all stocks are flagged demo) | Reads `stocks.csv` + `prices.csv` / `prices/*.csv`. Works fully offline. |
| `MockProvider` | `mock` | `MOCK` | Deterministic synthetic data (fictional `DM*` symbols). |
| `NepseProvider` | `nepse` | `LIVE` | HTTP adapter for a licensed vendor or your own gateway (`NEPSE_API_BASE_URL`); schema-validated responses, token-bucket rate limit (`NEPSE_RATE_LIMIT_PER_MINUTE`). NEPSE has no official public API; the expected JSON contract is documented in `packages/market-data/src/providers/nepse.ts`. |

The worker's `market-data-sync` job pulls symbols and recent candles from the configured provider
(admin: *Jobs & sync → Run data synchronisation*, or daily at 15:15 NPT when not using CSV).

Data-source labels (`LIVE`, `HISTORICAL`, `MOCK`, `IMPORTED`, `DEMO`) are stored per price row and
surfaced throughout the UI. Demo data is always shown as **DEMO DATA**.

## CSV import

Format (header required, extra columns ignored):

```csv
symbol,date,open,high,low,close,volume,turnover
NABIL,2026-01-01,500,510,495,505,120000,60600000
```

Flow (Admin → Data import, or `POST /api/v1/admin/imports` then `POST /api/v1/admin/imports/:id/commit`):

1. **Preview** — validates without writing: required columns, `YYYY-MM-DD` dates, numeric fields,
   negative values, OHLC consistency (`high ≥ max(open, close)`, `low ≤ min(open, close)`),
   duplicate rows, unknown symbols (unless "create stocks" is ticked), missing values. Rows already
   in the database and >15% day-over-day moves are flagged as warnings (never altered).
2. **Commit** — batched `INSERT … ON CONFLICT (stock_id, date) DO UPDATE` (idempotent), derived
   `previous_close/change/change_percent` recomputed, derived index rebuilt, signals regenerated by
   the worker. Files with more than 5,000 valid rows are committed by the `csv-import` background job.

Rows whose symbol is `NEPSE`, `SENSITIVE`, `FLOAT` or `SENFLOAT` are stored in `market_indices`
(close = index value). When an official `NEPSE` series exists the dashboard shows it; otherwise it
shows a clearly labelled *derived equal-weight composite*.

## Data quality

`GET /api/v1/stocks/:symbol/quality` reports missing trading days (using the configurable market
calendar — trading weekdays + holidays, never "every weekday"), duplicate candles, invalid OHLC,
negative/zero volume, non-positive prices and extreme moves. Suspicious data is flagged, not changed.

## Demo data

`data/sample` contains 18 fictional stocks × 3 years generated by `scripts/generate-demo-data.ts`
(seeded GBM + market factor, ±10% circuit respected). Symbols and names are explicitly marked
DEMO so synthetic prices can never be mistaken for real NEPSE history.
